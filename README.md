# Барбершоп «Висок»: демо-сайт и шаблон

Сайт барбершопа с онлайн-записью и админкой. Заведение, люди, адрес и отзывы вымышлены, это демо для портфолио и шаблон для перепродажи.

- Сайт: Vite + ванильный JS, анимации на anime.js (первый экран) и Motion (всё остальное).
- Данные и запись: Supabase (Postgres, Auth, Storage, Realtime), бесплатный тариф.
- База готова к Telegram-боту, подробности в [BOT_INTEGRATION.md](BOT_INTEGRATION.md).

## Запуск у себя

```bash
npm install
cp .env.example .env   # вписать URL проекта и publishable-ключ Supabase
npm run dev
```

`npm run build` собирает `dist/`. При сборке услуги, мастера, галерея и отзывы вшиваются в HTML: страница сразу показывает содержимое и индексируется поисковиками. В браузере данные потом обновляются из Supabase, так что правки из админки видны без пересборки.

## Структура

| Файл | Что внутри |
|---|---|
| `src/config.js` | Всё, что меняется под клиента: название, контакты, адрес, часы, соцсети, цвета, логотип, плашка демо |
| `index.html` | Разметка страницы и короткие тексты секций |
| `src/render.js` | Разметка прайса, мастеров, галереи и отзывов (общая для сборки и браузера) |
| `src/main.js` | Первый экран (anime.js), появление блоков, лайтбокс |
| `src/booking.js` | Онлайн-запись по шагам |
| `admin.html`, `src/admin.js` | Админка |
| `supabase/migrations/` | Схема базы, права, функции записи и демо-данные |
| `public/img/` | Фото первого экрана, мастеров и работ (источники в [CREDITS.md](CREDITS.md)) |

## Как устроена запись

1. Клиент выбирает услугу, мастера (или «любой свободный»), день и время, оставляет имя и телефон.
2. Свободное время считает функция `get_free_slots` в базе: график мастера, перерывы, выходные, длительность услуги, уже занятые записи.
3. Запись создаёт функция `create_booking`. Она проверяет телефон, время и слот, ограничивает частоту записей с одного номера и отсекает ботов по скрытому полю. Прямой записи в таблицу у сайта нет.
4. Две записи к одному мастеру на пересекающееся время база не примет физически: на таблице стоит exclusion constraint. Отменённые записи время не занимают.
5. Записи с телефонами видит только админ (RLS). Время хранится в UTC, часовой пояс заведения лежит в `settings.timezone`.

## Админка

Адрес: `/admin.html` (ссылка «Вход для сотрудников» в подвале сайта).

1. Ввести почту и нажать «Прислать ссылку», затем открыть письмо на том же устройстве.
2. Войти может только почта из таблицы `admins`. Добавить администратора: Supabase → SQL Editor →
   `insert into admins (email) values ('почта@пример.ru');` (почта строчными буквами).
3. Разделы:
   - **Записи:** список по дням, смена статуса (новая, подтверждена, пришёл, не пришёл, отменена), «Добавить запись» для звонков и визитов без записи. Новые записи с сайта появляются сами, без перезагрузки.
   - **Услуги, Мастера, Галерея, Отзывы:** добавить, изменить, удалить. Фото загружаются с телефона или компьютера, админка сама ужимает их до 1600 px. Галочка «Показывать на сайте» скрывает без удаления.
   - **График:** часы работы каждого мастера по дням недели, несколько интервалов в день (перерыв), выходные и отпуска для мастера или всего заведения.

Для входа по ссылке в Supabase должен быть указан адрес сайта: Authentication → URL Configuration → Site URL = адрес сайта, Redirect URLs = `https://адрес-сайта/admin.html`.

## Как перекрасить шаблон под нового клиента

1. **`src/config.js`:** название, район, телефон, адрес, координаты для карты, часы, парковка, соцсети, `priceRange`, цвета в `colors`. Для реального клиента `demo.enabled = false`.
2. **Логотип:** положить файл в `public/img/` и указать путь в `logo`. Если логотипа нет, остаётся бритва с названием.
3. **Фото:** заменить `public/img/hero-800.webp` и `hero-1400.webp` (первый экран), `tools.webp` (у прайса), `public/og.jpg` (превью в мессенджерах, 1200×630), `public/favicon.svg` и `apple-touch-icon.png`.
4. **Тексты секций:** в `index.html` (подписи к прайсу, мастерам, работам).
5. **Новый проект Supabase:** выполнить `supabase/migrations/001_schema.sql`, затем свои данные (или `002_seed.sql` для демо), вписать URL и ключ в `.env` и в переменные хостинга, добавить почту клиента в `admins`.
6. **Данные:** услуги, мастера, график, фото и отзывы клиент заводит сам в админке.

## Ключи

В браузер попадает только publishable-ключ (`VITE_SUPABASE_PUBLISHABLE_KEY`): с ним можно читать опубликованное и вызывать две функции записи, остальное закрыто RLS. Ключ service_role нужен только будущему боту и хранится на его сервере.
